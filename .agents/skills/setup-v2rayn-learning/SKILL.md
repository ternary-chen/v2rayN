# 配置 v2rayN 定制版

使用用户已有的订阅或节点，完成 Windows WPF 或 macOS Avalonia 客户端安装、默认分流、自动学习和 Codex 系统代理验证。服务器可能由用户自建，不需要登录服务器、安装 Xray 服务端或改动服务器配置。

先读取仓库根目录的 `docs/limited-learning.md`，核对当前版本能力；该文件与本 skill 随同仓库分发。这里的路径均相对当前下载的仓库或本 skill，不能套用作者电脑的安装目录、端口或节点名。

## 平台选择

先识别操作系统与架构。Windows 使用下文流程。macOS Apple Silicon（M1/M2/M3/M4，`arm64`）先读仓库 `docs/macos-learning.md`，下载 [ARM64 测试版](https://github.com/ternary-chen/v2rayN/releases/tag/v7.25.6-learning.5)，按该文档安装、配置和验收；以下订阅索取、默认规则、学习逻辑、备份与不断网切换原则同样适用。Mac 不执行 Windows 注册表/计划任务步骤，不复制 Windows 路径和进程名，不下载安装 Windows ZIP。核实 macOS 15 或更新系统，确认包摘要，保留原代理直到测试通过；不关闭系统安全策略。包为 ad-hoc 签名而非 Apple 公证版本。Intel Mac 不使用此 ARM64 包，先说明当前没有该架构的定制发布包。

## 输入与适用范围

- 优先使用用户本次提供的订阅链接或已指定的现成节点；已授权本机配置中有明确对应的订阅时可复用。**不知道链接且没有可用的已指定节点时，向用户索取订阅链接**，例如：“请提供要用于这个定制版的订阅链接；如果只有单个节点的分享链接，也可以提供。”在收到前可完成本地只读检查，不能猜链接或停用现有代理。
- 多个节点中，使用用户指定的专用节点；未指定且无法确定时询问。不要默认其他人的节点也叫“美国专线”。未启用双策略时，应代理的流量使用该节点的标准 `proxy` 出站；启用双策略后 AI 使用独立的 `ai-policy` 出站，其他代理与学习使用默认节点。
- 本流程目标是标准 Xray 配置、非 TUN 模式。检查实际协议及当前内核能力；订阅格式名称不等于协议兼容。无法导入、需要不支持的插件或仅有其他内核可用时，说明具体限制，索取兼容链接或节点，保留现有连接。
- 订阅 URL、UUID、密码、Reality 密钥材料、完整运行配置属于用户本地配置。不要上传在线订阅转换器、写入仓库/提交/公共报告，或在命令输出里回显。下载失败时只报告脱敏原因。
- 用户明确要求安装并替换客户端即可按此流程执行；仅让解释或检查时不切换。已有授权不用反复确认；遇到真正缺失的输入或相互冲突的选择再询问。

## 检查与准备

1. 发现实际安装位置、进程、监听端口、系统代理/PAC、TUN、开机启动项，以及 Codex 当前是否依赖 Clash。读取中文配置时显式使用 UTF-8，必要时识别 BOM。只获取相关配置，不打印整个配置数据库。
2. 将原客户端配置、选中订阅/节点、TUN 和系统代理状态、启动项以及要修改的 Codex 配置备份到仓库以外的本地私有目录。SQLite 使用在线备份或停程序后备份，不能只复制正在写入的主数据库而忽略 WAL。
3. 优先从 [Windows x64 定制版 Release](https://github.com/ternary-chen/v2rayN/releases/tag/v7.25.6-learning.5) 下载便携包并核对随附 SHA-256。通过包内 `build-info.json` 核对构建提交，使用 learning.3 或更新的定制包。确认客户端确实来自此 fork 且包含“设置 → 自动分流与 Codex 代理”、确认次数和永久记录功能。上游官方安装包不包含本分支功能；README 中保留的上游下载地址不能当作定制包。没有可信的对应构建产物时，从用户下载的分支构建 Windows WPF 项目，遵守用户对编译/打包的授权要求，不能虚构 Release 下载地址。SDK 版本以 `global.json` 为准，内核与 geo 数据另行核对。
4. 首次安装放在独立目录，使用空闲的本地端口。先让 Clash 继续提供连接，不启用新客户端的 TUN、不让两个程序同时自动写系统代理。优先通过客户端导入订阅和选择节点；离线修改配置数据库前必须停止对应程序，避免内存配置回写覆盖。

## 默认规则与学习

**默认使用本 skill 的 [assets/default-routing.json](assets/default-routing.json)，不默认迁移对方 Clash 的路由，也不直接使用全局代理或上游“绕过大陆”作为替代。** 用户另有明确要求时才调整。此文件是本 fork 当前使用的明确规则快照，属于安装预设，不会自动订阅更新。

在“设置 → 路由设置”中新建一个独立方案（如“默认分流与自动学习”），进入该方案的规则编辑界面，将 JSON 数组通过支持的文件/剪贴板导入入口导入空方案并保存、选中。若现有方案非空，避免追加到旧的兜底规则之后。其导入格式是 `List<RulesItem>`，不是完整的 Xray 配置、Clash YAML 或 `RoutingTemplate` 包装对象。离线导入必须依据当前源码的模型和选择机制，不能假定只写 `RoutingIndexId` 就生效。

保留规则顺序和 `domain:`/`full:`/`keyword:` 匹配语义，设置域名策略 `AsIs`，最后为无条件 direct。当前预设共 1433 条规则（982 条 proxy、451 条 direct），不含作者的程序目录、节点、订阅或学习历史。苹果/微软多数服务直连，部分具体服务有更早的代理例外；判断结果以首条匹配为准，不能仅按品牌名下结论。

在“设置 → 自动分流与 Codex 代理 → 自动分流”中：

- 勾选“启用自动检测与代理记录”，保存并重载。程序出厂默认关闭此功能，导入 JSON 本身不会开启学习。
- 默认直连检测 2500 ms，代理检测 8000 ms，临时记录 24 小时，容量 2000。学习监听默认 17880，专用 SOCKS 入站默认 17881；检查它们与主入站及其他程序无冲突，均只绑定 loopback。主代理端口以实际配置为准。
- 保留默认强制直连进程：向日葵、UU 远程、异环及所列辅助程序。按目标机器实际安装目录补全需要覆盖的辅助程序目录，使用 `/` 分隔并以 `/` 结尾，不复制作者的绝对路径。进程规则只对进入该代理且内核能识别进程的连接生效；没有进入代理的流量由应用自身联网，不宣称能控制全机所有流量。
- 规则处理顺序为：强制直连应用 → AI 厂商规则（启用双策略时）→ 现有明确规则 → 未匹配 TCP 80/443 的自动检测 → 其余 direct。学习模块另有内部强制代理入站避免循环，由代码生成，不手工复制到预设。
- 未匹配网站先测直连，失败后测代理；仅“直连失败、代理成功”新增确认。双方失败不新增代理记录，已有累计历史保留。临时有效期内重复访问和并发连接不重复计数，到期后再次独立确认才加一次；同一主机名、端口、节点累计 5 次后永久保存。换节点不共享计数，手动删除记录清零。
- 不导入作者的 `limited-learning.json`。首次安装从空记录开始；升级用户自己的客户端保留其记录。已有显式 direct/proxy/block 都不参与学习，永久记录也不能覆盖它们。

HTTPS 仅验证独立 TLS 握手和证书，HTTP 检测响应，不使用 ping 判断网站是否可用，不解密 HTTPS、不重放用户 POST/上传。TCP/TLS 可达但内容受限、验证码、HTTP/3 和其他端口不在自动判断范围内。

## AI 与默认双策略

若用户要求 AI 专线与日常代理分开，先读取仓库 `docs/ai-policies.md`。确认安装的版本已有“策略组”页；之前 learning.1 / learning.2 发布包不含此功能，不在旧包上假装已配置。使用新版本时，在“策略组”页选定 AI 专线和默认日常节点并启用；默认节点由用户指定，缺少选择时询问，不猜哪个节点免费。默认策略与主列表选中节点保持一致，AI 节点单独保存。自动学习始终使用默认出口，保留每默认节点独立的历史。

AI 主名单使用 v2fly 社区厂商 geosite 分类，并合并已整理的精确补充；通过现有 Geo 数据更新入口维护。不要导入整个 GLaDOS Research + AI 组、整个 Google/Microsoft 组或 category-ai 总集合。对应厂商、来源提交、补充和更新边界见 ai-policies.md。保存前检查两个节点可用性，先完成离线配置预检再安排重载和回退。

## Codex 与网络切换

先完成新节点的独立代理测试，再切换系统代理。测速成功或 TUN 仍开着时的访问成功，均不能证明已经独立替代 Clash。

1. 在定制版 Codex 设置页确认正在运行的实际 `codex.exe` 和配置目录，优先使用该页“启用系统代理支持”。它备份配置并设置 `[features] respect_system_proxy = true`，不会修改 `.env` 或认证信息。运行时路径会随升级变化，不能固定 WindowsApps 或带版本哈希的旧路径。不支持该能力/诊断命令的版本应根据当前运行时与官方文档处理，不绕过管理策略。
2. 检查进程、用户环境变量和 Codex `.env` 中是否有指向旧 Clash 端口的 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY。只调整确定已失效且属于本次迁移的项，先备份，保留其他变量和用户仍需的代理设置。不创建强制启动器或用旧端口 `.env` 掩盖连接问题。
3. **Codex 本身可能走旧代理。先在本机保存并启动一个不依赖后续聊天调用的切换/回退脚本或等价监督流程**：记录旧状态；切换系统代理至新端口；关闭 Clash TUN 并退出其核心；在有界时间内检测新客户端、代理请求和路由；失败则恢复旧程序及原系统代理/TUN状态。回退必须实际能恢复所用客户端，不能只写一句“失败时再让 Codex 重开 Clash”。只按核实的完整路径/PID处理相关进程，不批量杀死所有代理程序。无法可靠自动恢复时，先向用户说明并提供可本地执行的恢复步骤，再由用户配合完成高风险切换。
4. 启用定制版的“自动配置系统代理”，保持 TUN 关闭。切换前说明会短暂断开；新程序与旧程序同机存在不等于验证成功。关闭 Clash 后再次验证，核对无残留 TUN 默认路由或旧核心承载外连。
5. 如 Codex 配置或继承环境发生变化，先保存进度与恢复办法，再让用户完全退出并重新启动 Codex。不要由正在工作的代理强行关闭自己的宿主。重启后在同一任务继续验收；未重启时明确列为待验收，不能伪称已完成。

## 验证与交付

- 对照实际生成的 Xray 配置确认：目标节点、默认预设、程序直连规则、学习入口、内部代理入站和最终 direct；不得在报告中输出节点凭据。需要时仅对生成配置运行内核配置检查，不重跑全仓库测试。
- 在旧核心和 TUN 关闭后，测试一个明确代理的网站、一个明确直连的网站及一个未匹配的公开网站；核对 `[自动分流]` 日志与实际连接。学习记录只在条件真实成立时才产生，不为了展示效果篡改记录、关闭证书校验或故意破坏直连。
- 用“检测 WebSocket 握手”或当前运行时支持的 `doctor --json` 验证 Codex，输出脱敏结论。HTTP 101 只说明握手成功，还需确认正常 Codex 会话恢复；不能承诺所有网络路径或长期稳定性。
- 用户要求替代 Clash 日常启动时，验证通过后将定制版设置为开机启动、启动后隐藏窗口，关闭 Clash 的自启（核对实际注册表/计划任务/客户端设置），保留旧客户端与备份供恢复。Codex 保持用户手动启动，除非另有要求。
- 报告安装位置、构建来源、所选节点名称、默认规则与学习是否启用、系统代理端口、实际验证结果、待用户完成的步骤和恢复入口。不要把“安装完成”“TUN 下访问正常”和“独立代理验证通过”混为一谈。

## 维护依据

- 仓库 `docs/limited-learning.md`、`v2rayN/AdaptiveRouting/{LearningOptions,XrayLearningConfig,LearningStore,CodexProxySupport}.cs`。
- 导入/选择路由参考 `v2rayN/ServiceLib/ViewModels/RoutingRuleSettingViewModel.cs` 与当前路由管理代码；订阅导入使用客户端现有功能。
- Codex 技能发现与使用方式：[OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。本 skill 放在仓库 `.agents/skills` 下，下载仓库后在该仓库中打开 Codex 即可发现；也可让 Codex 直接读取本文件。

## 定制版更新

learning.5 起使用本 fork 的定制更新入口：自动检查和下载，用户在“检查更新”页确认后才安装。首次安装应使用含 CustomUpdater 的完整包；不要用官方客户端更新覆盖此版本。详见 [仓库更新说明](../../../docs/custom-updates.md)。
