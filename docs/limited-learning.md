# 自动分流与 Codex 系统代理

本分支基于 v2rayN 7.25.6。Windows WPF 与 Avalonia 客户端均在“设置 → 自动分流与 Codex 代理”提供入口。默认关闭学习，保留官方节点、订阅和 Xray 内核更新方式。macOS Apple Silicon 测试版的安装、签名和实机验收边界见 [Mac 说明](macos-learning.md)。

双策略配置与持续更新的厂商名单见 [AI 与默认策略](ai-policies.md)。

## 分流语义

1. 配置的强制直连进程优先于网站规则。默认包含向日葵、UU 远程与异环主进程及服务。该名单在关闭学习后仍保留；可以在窗口中编辑。需要覆盖辅助程序时，可以增加应用的绝对目录（使用 `/` 并以 `/` 结尾）。
2. 现有路由中所有明确的域名、IP、端口和协议规则保留原顺序。明确的 direct、proxy、block 不参与学习。
3. 仅在最后的无条件 direct 之前插入 TCP 80/443 的未知网站入口。若没有无条件规则，插入学习入口后以 direct 兜底。无条件 proxy/block 的路由拒绝启用学习，不悄悄改变全局代理意图。
4. 未知网站先尝试直连；只有直连检测失败、代理检测成功才记住“具体主机名 + 端口 + 节点身份”。不会扩大到父域名或整个应用。
5. 代理检测使用独立的 loopback SOCKS 入站，第一条路由将此入站强制送到当前选中节点的 `proxy` 出站，避免再次落入默认直连或形成学习循环。

学习不下载新社区规则，也不把规则列表里的显式 direct 当成未知。请先使用自己认可的社区路由或迁移后的路由。更新路由后，其明确规则始终先于学习记录，因此自然覆盖旧学习决定。

## 检测和限制

- 当前只支持标准 Xray 配置、非 TUN 模式。不开启或接管其他 VPN/TUN；使用本功能前应关闭其他客户端的 TUN。
- HTTPS：独立连接上验证 TLS 证书和握手。HTTP：独立发送 `HEAD /`，收到有效 HTTP 状态行即视为连通，包括 4xx/5xx；不据此判断内容是否可用。
- 实际应用请求在选路完成后才开始转发；不进行 HTTPS 中间人解密，也不重放原始 POST、上传或表单。建立后的隧道发生故障时直接结束，由应用处理。
- TCP/TLS 可通但内容被限制、验证码、需要登录、HTTP/3、非网页端口不在自动识别范围内。非网页未命中流量保持 direct。
- 不学习 IP、局域网名或解析为私有地址的主机；IPv4、IPv6、映射 IPv4 均检查。
- 首次未知网站增加探测开销。默认直连限时 2.5 秒、代理限时 8 秒；私网检查可能单独等待一次 DNS。成功直连缓存 5 分钟；双方失败冷却 20 秒。
- 临时代理记录默认 24 小时到期，累计确认次数在到期和重启后保留。只有到期后再次确认“直连失败、代理成功”才增加一次，缓存命中和并发请求不会重复计数。累计 5 次转为永久记录，不再自动过期。计数按具体主机名、端口和节点隔离；切换节点不会复用其他节点的计数。手动删除记录同时清零次数。
- 模块最多承载 128 个连接，已建立隧道不因固定空闲期限而被关闭，使用 TCP keepalive；WebSocket、SSE 和原始 TLS 字节双向透传。只限制建连/探测时间，退出或重载时取消连接。已明确分类的服务完全绕过此模块。
- 数据保存在客户端独立配置目录的 `limited-learning.json`。保存主机名、端口、节点身份摘要、时间、累计确认次数和检测依据，不保存网页路径、凭据、正文或节点密钥。旧版记录读取为 1 次确认，保留原到期时间。
- 默认容量 2000 条，包含到期历史。新增记录需要空间时先淘汰最旧的非永久记录，永久记录不自动淘汰；全部为永久记录且已满时，本次仍可使用验证成功的代理并短暂缓存，但不再新增持久记录。实际代理连接失败不会删除已有计数，也不会额外增加次数。
- 日志区区分首次检测、直连缓存、临时/永久代理记录、失败冷却、两路检测结果、耗时、实际隧道建立以及失败阶段。启用应用日志时，`[自动分流]` 记录同时写入 `guiLogs` 的每日文件；不记录网页路径、请求正文或账号凭据。
- 永久记录和临时记录一样，只在现有明确规则均未命中时使用。新增的手动或社区规则仍可覆盖它。
- 不修改当前节点。若需要所有代理流量使用“美国专线”，选中该节点，并让现有代理规则使用默认 `proxy` 出站。

## Codex 系统代理

Codex 代理页本身不修改域名名单；启用双策略后由 AI 厂商规则指定出口，未启用时仍由现有社区规则处理。

- 显示当前系统代理与 v2rayN 本地端口。macOS 使用只读 `scutil --proxy`，显示 HTTP/HTTPS/SOCKS/PAC 状态，不显示 PAC URL 或凭据。
- 优先检测正在运行的 Codex 桌面版子进程，找不到时允许选择实际 `codex` / `codex.exe`；macOS 支持选择包含唯一运行时的 Codex/ChatGPT `.app`。
- 备份 `config.toml` 后，只将 `[features] respect_system_proxy` 设置为 `true`。不更改 `.env`、认证信息、提供商、其他配置或系统代理。Unix 上保留原配置文件权限，新建文件和备份默认仅用户可读写。
- 配置改写是保守的：多行 TOML 字符串、重复段、内联/带引号的特殊 features 写法会被拒绝，提示手动修改，而不是猜测解析结果。
- 重复启用不会覆盖原恢复记录。恢复前核对文件摘要，存在后续用户修改时拒绝覆盖。
- 诊断调用选中的运行时 `doctor --json`，不发起模型任务；最多 60 秒，关闭窗口取消并结束诊断子进程。仅展示网络诊断的安全字段。清除诊断进程继承的代理变量，但保留 Codex 自身 `.env`，若检测到其中含代理变量会提示。
- 用户需在主窗口启用系统代理，并完全退出、重启 Codex。工具不会自动关闭 TUN 或重启 Codex。HTTP 101 仅证明握手，不代表长会话、MCP、浏览器控制等路径全部通过。

## 开发验证

```powershell
dotnet run --project v2rayN/AdaptiveRouting.SmokeTests/AdaptiveRouting.SmokeTests.csproj
dotnet build v2rayN/v2rayN/v2rayN.csproj -c Debug
```

这些是新功能的针对性检查和 Debug 编译，不运行原项目全量测试、不执行发布打包。测试使用临时目录与本地 SOCKS 服务；包含真实 POST 转发且只提交一次、WebSocket 字节透传、跨到期周期累计、重启迁移、并发计数、第五次晋升和日志分支检查。

发布包与现用客户端分目录部署，配置迁移前备份。关闭学习并重载后，学习监听与专用入站退出；强制直连进程仍保留。Codex 设置可以使用本功能的恢复入口还原。

## Windows 启动与切换

在“设置 → 参数设置 → v2rayN 设置”启用“开机启动”和“启动后隐藏窗口”，并保持系统代理为“自动配置系统代理”，即可在登录 Windows 后运行到托盘。其他代理客户端可关闭自动启动，保留手动使用。

Codex 可以正常手动启动，不需要专用启动器。切换代理客户端时，应检查用户级环境变量及 `.env` 是否仍指向旧端口；如有修改，需要完全退出并重新打开 Codex，让新进程取得更新后的环境。当前设置页面不会自动修改用户级环境变量。

官方客户端更新会覆盖本分支的定制功能。需要保留定制功能时，从此 fork 构建客户端；内核和规则数据可独立更新。

## 实机验证边界

2026-10-21 的本机验收中，Clash 代理端口已关闭，当前运行环境没有旧代理变量；观察到 Codex 桌面及运行时连接定制版端口，Xray 外连经物理以太网默认路由，WebSocket 返回 HTTP 101。此结果只代表当次连通性，长会话稳定性仍需持续使用验证。个人订阅、节点配置和运行日志未提交。
