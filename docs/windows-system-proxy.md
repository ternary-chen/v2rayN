# Windows 系统代理操作与验收

底部“代理操作”是用户发起的动作；上方 Windows 状态独立从系统读取，每两秒刷新。开启时显示实际地址，鼠标悬停显示 WinINet、注册表和 WinHTTP 当前用户配置。三处不一致时显示“代理配置不一致，请重新应用”；读取失败显示读取失败，不当作关闭或开启。

## 每次操作

- Windows/WPF 与 Avalonia 的“自动配置系统代理”“清除系统代理”支持重复点击。不同选项走选择事件；同一选项走显式命令，不依赖 SelectionChanged。展开下拉框后按 Enter 也可重新执行当前项。
- UI 请求串行处理，使用该次请求的模式。回读验证通过后才保存操作模式、发送成功提示；失败保留原模式并报告错误。程序更新选择值不触发新的写入。
- Windows 写入先处理拨号连接，再处理默认连接与注册表，最后统一通知刷新。写入有进程内互斥，最多两次尝试；通过一次回读后，100 ms 后再次确认。不会在后台持续抢写系统设置。
- 完整回读包括 WinINet 的标志、地址、PAC、绕过规则；注册表的 ProxyEnable、ProxyServer、AutoConfigURL、ProxyOverride；WinHTTP 当前用户代理配置。WinHTTP 此处不是机器级的 netsh winhttp 代理，不修改机器级服务代理。
- 清除要求手动代理、PAC、自动检测都关闭，代理地址、PAC、绕过规则无残留。自动配置要求三处均与请求的代理地址/绕过规则一致。
- 日志记录请求模式、操作前状态、重试读数和验证结果。凭证或查询参数不会原样出现在代理状态日志中。

其他软件以后修改系统代理时，状态刷新会反映变化；客户端不自动抢回。系统代理关闭不代表 TUN 关闭，也不强制中断已有代理连接或停止 v2rayN 内核。

## 内置检查入口

底部 Windows 实际状态旁的“检查代理”打开系统代理检查窗口。提供“查看当前状态”“验证已清除”“验证自动配置”和“保存本次报告”。报告包括检查时间、期望模式、三处开关/地址/PAC/绕过规则、差异项目、本地端口监听与具体结论。端口和代理协议从当前配置读取，不写死为 18808；没有监听与配置不一致分别报告。检查不修改代理、不停内核、不访问公网，报告可离线保存成 UTF-8 文本。

Windows/WPF 和 Windows 上的 Avalonia 都有此入口；非 Windows 的 Avalonia 隐藏该 Windows 专用检查入口。若系统读取失败，窗口明确显示无法确认，仍可保存错误报告，不保留过期的成功结果。

## 定向验证

`SystemProxy.SmokeTests` 默认使用内存中的状态样本验证不一致检测、目标模式检查、PAC、自动检测、绕过规则和私密参数隐藏。`--read-only` 额外读取当前 Windows 三处设置，不做写入。可追加 `--expect-clear` 或 `--expect-enabled`（期望端口 18808）。本测试不初始化现用配置数据库，不进行外网请求。旧的会改写系统代理的 `--live-authorized` 路径已移除。

`work/Check-SystemProxy.ps1` 是不依赖 .NET SDK 的离线验收脚本，支持 `-Expected Clear`、`Enabled`、`Inspect`。脚本列出每处实际读数和不一致项，检测 18808 是否监听，并将带时间的文本报告保存在脚本目录。它只读取系统设置，不测试公网连通，不改变 Clash 或 v2rayN。

验收顺序：

1. 保持 Clash TUN 开启，先不要退出 v2rayN。选“清除”，运行 Clear 检查；再点同一个“清除”并再次检查。
2. 选“自动配置”，运行 Enabled 检查；再点同一个“自动配置”并再次检查。
3. 对比各次报告。清除模式中端口仍监听是正常的；开启模式中配置正确但端口没有监听会明确报告入口不可用。
4. 路由日志和实际网站访问另行验证。配置通过不代表登录、节点、WebRTC 或 UDP 均正常；应用也可能复用旧连接。

本次源码修改不等于已部署。安装时继续保留 guiConfigs、guiBackups、binConfigs、bin；通过 Windows 原生方式启动客户端，避免依附于 Codex 工具进程。
