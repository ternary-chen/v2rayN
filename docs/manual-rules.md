# 统一规则管理

入口：设置 → 规则管理与自动分流 → 规则管理。Windows WPF 和 Avalonia 共用同一配置模型、校验和保存服务。

界面参考 Clash Verge Rev 的可视化规则编辑方式（类型、匹配内容、策略、前置列表），不导入 Clash YAML：
- https://www.clashverge.dev/guide/rules.html
- https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src/components/profile/rules-editor-viewer.tsx

## 使用

1. 在页面上方选择默认代理和专线节点。主窗口切换节点只改变默认代理；专线按节点 ID 保存。
2. 左侧选择规则类型、填写匹配内容、选择默认代理 / 专线 / 强制直连。点击添加到列表顶部。
3. 选中列表中的规则可编辑、停用、删除、上移或下移。列表从上到下匹配，第一条命中生效。编辑后点更新，再保存。
4. 点击“保存规则（不中断连接）”会通过 Xray RoutingService 原子替换规则，并回读确认；页面保持打开。内核进程、已有连接及自动学习服务不会重启，新连接使用新规则。表单未添加/更新时会提示。
5. 切换默认/专线节点时，规则保存按钮会拒绝重启。使用独立的“应用节点变更并重启”按钮才会保存节点并走原重启流程。
6. “启用内置 AI 网站规则”只控制内置分类。关闭后手动专线仍有效；没有启用的专线规则时不强制要求专线节点。

支持完整域名、域名及子域名、域名关键词、IPv4/IPv6/CIDR、geosite、geoip、进程名称和程序目录。域名直接填写 example.com，不含协议、路径或 domain: 前缀。Windows 进程 .exe 后缀会去除；目录统一为 / 分隔并补齐结尾 /。分类须存在于本机 Geo 数据。IP 规则对域名连接的匹配受原路由 DNS 解析策略影响。

## 优先级与兼容

普通流量：受保护程序直连 → 本页手动规则 → 内置 AI 分类 → 原路由规则 → 未匹配 TCP 80/443 自动学习 → 原路由兜底。
内部学习探测入口始终先固定到默认出口，避免手动规则引发循环。受保护程序名单移到本页折叠区，内容和最高优先级保留；关闭自动学习后仍有效。进程匹配仅覆盖已进入代理且内核可识别的连接。

手动规则独立存储在 guiNConfig.json 的 ManualRules，不覆盖订阅或原路由集。旧配置缺少此字段时为空列表。原路由集继续在“设置 → 路由设置”维护。默认/专线分别映射到 proxy / ai-policy，专线节点缺失会在保存预检时报错，不回退到默认出口。

延续定制分流的支持范围：标准 Xray 单节点、非 TUN。启用规则时遇到 sing-box、自定义配置、TUN 或复杂节点会明确拒绝，不静默忽略规则。保存前执行格式校验和真实配置生成；备份原配置后保存，失败恢复内存设置。Geo 分类可用性与真实连通性需使用实际内核进一步验证。

定向验证：PolicyIntegration.SmokeTests，使用其独立构建目录、测试数据库和虚拟节点，不启动代理或写入现用安装目录。

## 规则热更新

标准 Xray 启动时启用仅监听 127.0.0.1 随机端口的 RoutingService。客户端保存已启动内核的配置快照与进程对象，和内核启停共用互斥锁。只允许 routing.rules 变化；节点、DNS、监听及其他配置变化会明确拒绝热更新，不自动回退到重启。

有效的已选专线出口即使暂未被规则使用也保留在内核中，这样开启/关闭内置 AI 或增删手动专线规则无需改动出口。首次配置或更换节点仍需正常加载节点。

使用运行内核同一可执行文件的 api adrules --append=false 一次替换完整规则，不执行“先删旧规则再加新规则”。规则末尾附加不可命中的 SHA-256 版本标记，lsrules 回读同时验证顺序、出口和版本，避免只改匹配内容却被误判为相同规则。API 失败不调用 CoreStop；响应丢失先回读核对。保存失败会回退旧规则；回退状态无法确认时明确报错，不声称成功也不重启。

已在 Xray 26.10.10 上做隔离真实连接验证：同一 PID 下默认 → 专线 → 直连，新连接改用目标出口；旧 TCP 流和自动学习代理流继续通信。还覆盖停用、排序、删除、仅改匹配内容、无效分类拒绝和模拟持久化失败回退。测试全程只用回环端口与本地模拟出口；代理/API 使用随机端口，学习流使用独占的临时 127.0.0.2:80 网页端点。

已有 HTTP keep-alive、HTTP/2 或 WebSocket 连接保持原出口，复用它们的请求也保持原出口；需要新建网络连接才会重新匹配规则。此验证不等于公网节点连通性或所有协议的端到端验收。

实现依据： https://github.com/XTLS/Xray-core/blob/v26.10.10/app/router/router.go 与 main/commands/all/api/rules_add.go。
